Liquid Glass Navbar

v0.11.2 New

A glass tab bar for the web, in the style of iOS. You write the buttons; it adds the glass, the sliding highlight and the swipe gesture. It's plain TypeScript and CSS, so it works with any framework or none.

Every example on this page is the real component. Tap the tabs, drag across them, move your pointer over them, and change the controls; the code below each example updates to match. Hover over an item or drag across the topic bar to preview its section. In Bar settings, you can set hover behavior for all topics and override individual topics. To design a bar visually and copy the result, use the builder.

Install

The package is installed from GitHub, not npm. Pin a tag:

npm install 'git+https://github.com/soheab-com/liquid-glass-navbar.git#v0.11.2'

It ships TypeScript and CSS, so use a bundler such as Vite, esbuild or webpack.

Quick start

Write a normal <nav> with buttons. Mark each icon with data-navbar-icon and each label with data-navbar-label, and mark the starting tab with aria-current="page". Then mount the bar.

mountLiquidGlassNavbar returns an object for changing the bar later. Call destroy() on it before removing the <nav>; that removes everything the navbar added.

Tabs, actions and sections

A tab is somewhere you go: picking it moves the highlight and calls onSelect. An action does something, like opening search: mark it with data-navbar-action and it calls onAction instead, without becoming the current tab.

Wrap groups of items in data-navbar-section elements to give each group its own glass pill. Items without a visible label need an aria-label.

Links as tabs

Use <a href> elements instead of buttons when every tab is its own page. Tapping a link, or ending a swipe on it, follows it like a normal click. Callbacks receive the link: NavbarItem is a button or a link.

<nav aria-label="Main">
  <a href="/" aria-current="page"><svg data-navbar-icon …></svg><span data-navbar-label>Home</span></a>
  <a href="/schedule"><svg data-navbar-icon …></svg><span data-navbar-label>Schedule</span></a>
</nav>

With a client-side router, pass autoSelect: false so the navbar doesn't move aria-current itself. Set it from your router, then call sync().

Position

position pins the bar to an edge of the screen, respecting safe areas. Leave it out to place the bar with your own layout. Change it later with setPosition().

Icons and labels

labels: false shows icons only. To hide the icon or label of one item, add data-navbar-hide-icon or data-navbar-hide-label, or call setItemVisibility(). Hiding both hides the item.

Equal width

equalWidth: true makes every tab as wide as the widest one, so the highlight is the same size everywhere. equalWidthOverflow decides what happens when that doesn't fit: return to natural widths, cut labels off with an ellipsis, or let the bar grow. Drag the width slider to see it.

Colors and glass

colors sets the selected and unselected colors, and optionally separate icon and label colors. background takes any CSS background to tint the glass. transparency runs from 0 (solid) to 100 (clear glass with only the rim, shadow and refraction).

In Chromium the rim refracts the live page behind it. Safari and Firefox use live blur and tint. The same settings are available as CSS variables; see CSS variables.

Swiping

Press a tab and slide. The highlight follows your finger and swells into a clear bubble, and only the part of a tab under it takes the selected color, so halfway between two tabs you see half of each. Lift to pick the item under it. Past the first or last item it stretches like a rubber band, and when you let go it keeps the speed of your finger as it settles.

Swipes cross sections and include actions. Add data-navbar-no-swipe to an item or section to keep it out; tapping and the keyboard still work there.

Reordering

With reorderable: true, a focused tab moves with Alt and the arrow keys. Call setReorderMode(true), for example from an Edit button, to let people drag tabs too. Tabs move within their own section, and onReorder receives the new order.

Magnify

magnify adds a Dock-style effect: icons near the mouse pointer or a sliding finger grow and rise away from the bar's edge, and settle again as it moves on. Each icon follows its own spring, so moving back and forth stays smooth. Only the icons move; the tabs, the highlight and the tap areas stay where they are.

Animations

The bar always moves with springs: the highlight, swipes and compacting. animations adds more motion on top, off unless you turn it on. Pass true for all of it, or choose:

  • reflow: items glide to their new place when they move between the bar and More, change rows, or the bar changes size.
  • popovers: More and anchored popovers, which always open on a spring, get a little overshoot.
  • tap: a pressed tab squishes a little, and a newly selected icon bounces.
  • badges: badges pop in, pulse when they change, and shrink away.

Every animation can be interrupted and turns around from where it is. None of it runs with Reduce Motion. The springs are exported as createSpring(), so your own motion can match. Drag the width slider and use the badge buttons.

Rows

layout: 'wrap' wraps the items into rows inside one glass surface. layout: 'rows' gives each row its own centered pill. The bar measures the real icons, labels, padding and gaps, so every item fits, and it reflows when the space changes. Drag the width slider.

Put an item or section on a specific row with data-navbar-row="1", "2" and so on. In a bar with sections, each row holds whole sections. Multi-row layouts apply to bars at the top or bottom, or bars you place yourself.

Use collapsible: true to put a chevron in the last row. Tap it to open or close the upper rows, or swipe the lens over it to preview the change. Configure which rows collapse and save the choice with onCollapse. The multi-row integration guide also covers responsive More limits, item updates, and lens appearance.

More

overflow moves the items that don't fit into a More button. The 'menu' style lists them in an anchored menu. The 'expand' style opens a row of glass icons, in one shared pill or each in its own glass. Limit the bar with maxRows (for multi-row layouts) or maxVisible. trigger: 'dots' shows the More button as a vertical ⋮ icon without a label. More stays open while the page scrolls, and a tap outside closes it; set closeOnScroll: true to close it as soon as the page scrolls.

The current tab stays selected when it moves behind More, and More shows that it holds the current tab. Slide onto More during a swipe and it opens, so the same finger can carry on into it. More closes on Escape, a tap outside, another tab, or a selection. Keep an item in the bar with data-navbar-overflow="never".

Popovers

createPopover(item, content, options) anchors a popover to an item in the bar, such as a Create action. Tapping or swiping to the item toggles it. A small pointer stays aligned with the item when the popover shifts away from an edge or flips to the other side.

For a trigger outside the bar, use the exported createAnchoredPopover(trigger, content, options). Both close on Escape, a tap outside, or a choice inside, and return focus to the trigger when it was inside. A finger that starts scrolling the page leaves them open; pass closeOnScroll: true to close on scroll instead.

Badges

setBadge(item, badge) shows a count, a dot or a status on an item; pass null to remove it. The label is announced with the item. When an item with a badge is behind More, More shows a dot.

Scroll compact

scrollCompact hides the labels while the page scrolls down and brings them back when it scrolls up or reaches the top. Small reversals under the threshold and rubber-band overscroll are ignored. Compacting only hides the labels: items behind More stay there, so the bar never reshuffles while you scroll. Pass the element that scrolls as source; the default is the window. Scroll the example.

Context actions

showContextActions(nodes, options) shows your own actions in the bar, for example while files are selected. Pass buttons, or data-navbar-section groups for separate pills. hideContextActions() removes them and brings back the tab that was selected before.

  • placement: 'replace' (the default) swaps out the whole navigation; 'start' and 'end' put the actions beside it; a section or item of the bar replaces just that part.
  • back: adds a Back item that returns to the previous items. { label, icon } changes it, and onBack runs when it's used.
  • className and look: give the actions' pills styles of their own, with colors, background and transparency.

Adaptive contrast

Mark content with data-navbar-backdrop, listing dark, light and/or busy, and turn on contrast. Over dark content the icons and labels switch to a readable color, even with clear glass. With adaptiveTint, busy content such as photos adds tint and quiet content clears it again. You can also report what's behind the bar yourself with setBackdrop({ tone, busy }). Scroll the example.

Bending the backdrop

The glass bends what's behind it along its rounded edge, like Liquid Glass on iOS: fully clear glass squeezes the backdrop into the bevel, tinted glass folds it over. Chromium bends the live page. Safari can't bend what's behind an element, so there the glass bends a copy of the elements you mark: data-navbar-refract for a fixed backdrop such as a wallpaper, data-navbar-refract="scroll" for content that scrolls under the bar, or pass your own elements with refractionSources. Content that scrolls is copied and moved from script, so on iOS it can trail a little during fast flicks. Call refreshRefraction() after copied content changes. While something is behind a piece of glass, its icons and labels get a soft halo so they stay readable, and over images its rim, highlight and shadow take the image's colour. Scroll the example.

Saving the tab

The navbar stores nothing itself. Save the tab in onSelect and restore it with select(item), which marks it as current without calling onSelect. It works for items behind More. Pick a tab, then press Reload.

Accessibility and motion

  • Items are your own buttons and links, so they keep their roles, focus order and keyboard behavior. Labels become accessible names automatically.
  • The current tab is aria-current="page". More and popover triggers carry aria-expanded and aria-controls.
  • Focus moves into a popover opened from the keyboard and returns to its trigger on Escape. Focus stays on items when they move between the bar and More.
  • Moving parts use springs, so interrupting them turns them around smoothly. With Reduce Motion they jump to the end, and magnify and the opt-in animations are off.
  • With Reduce Transparency the default glass becomes solid. An explicit transparency takes precedence.

Browser support

The navbar is built and tested in Chromium. Rim refraction of the live page is Chromium only; Safari and other browsers show the same glass with live blur and tint.
